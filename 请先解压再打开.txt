三、CNKI 论文库为什么首屏不加载（第四轮）
────────────────────────────────────────
  sports-cnki-data.ea3da788.js 原始 1.76 MB，但压缩后仍有 929 KB
  （压缩率仅 48.5%，其他文件都在 84~94%——因为它每条记录都带一串
   约 180 字符的加密 token，属高熵数据，压不动）。
  它一个人就占了全站压缩后体积的 60%，却只服务两个页面。

  因此改为「按需加载」：
    · index.html 里不再有它的 <script src> 和 <link rel=preload>；
    · 取而代之的是一个 20 行的 _cnkiLoad() 加载器，只有用户真正进入
      「学术期刊」或「学术动态」时才注入脚本并拉取；
    · 加载中会显示「正在加载论文库…」；失败则降级为不含论文的正常页面，
      不会白屏、不会死循环。

  效果（首次访问、浏览器无缓存）：
    改造前  10.02 MB 原始 / 1.514 MB Brotli
    改造后   8.30 MB 原始 / 0.628 MB Brotli     → 少传 58.5%
  已实测验证：首页 / 学术期刊 / 学术动态 三个页面的正文逐字节一致，
  控制台 0 报错，论文条数、期刊下拉、KPI 数字全部相同。

  说明：论文库本身仍会在用户点进那两个页面时下载一次，之后一年内
  由 EdgeOne 强缓存命中，不再重复下载。

────────────────────────────────────────
四、首屏为什么又快了（第五、六轮）
────────────────────────────────────────
  第五轮 · 学者数据脚本改 defer
    原来 <script src="sports-scholars-data…"> 是同步脚本：浏览器解析到
    这一行就得停下来，把 7.6 MB 下载并执行完，才继续构建后面的 DOM。
    而首屏（首页视图）其实一行学者数据都用不到。
    现在给「学者库」和「院校目录」两个脚本加了 defer —— 不阻塞解析、
    按文档顺序在 DOMContentLoaded 之前执行，全局变量在业务代码跑起来
    之前一定就绪，语义与原来完全一致。
    顺带把 3 处「解析期守卫」改写成可重入的命名 IIFE：它们原本在 HTML
    解析时同步执行，而 defer 脚本那一刻还没跑，守卫会直接判失败、补丁
    静默失效。改后依赖没就绪就注册 DOMContentLoaded 回调重试。

    实测（4 Mbps / 150 ms 延迟 / CPU ×4，n=3 取中位数）：
        domInteractive     2878 → 940 ms   -67.3%   ← DOM 开始可交互
        DOMContentLoaded   2879 → 2510 ms  -12.8%
        遮罩消失           4209 → 3695 ms  -12.2%
        load 事件          4203 → 3787 ms   -9.9%
    两组原始样本完全不重叠。

  第六轮 · 对比度自愈脚本提速
    页面里有两个「浅色对比度自愈」脚本，要遍历整棵 DOM、逐元素向上找
    有效背景色、算对比度，不够就改写文字颜色。V8 采样剖析显示它们占了
    整页 CPU 的约 77%（effBg 3275ms + fixOne 3094ms + …）。

    三处等价改造：
      · effBg 记忆化 —— 这页 DOM 最大深度只有 12，远小于原实现的 48 层
        截断上限，所以改成带缓存的递归后逐元素结果完全相同；
      · csOf 缓存 getComputedStyle 返回的活对象（读取永远反映最新状态）；
      · 两阶段「先全量判定、再批量写内联色」—— 这是关键。原来每写一次
        style.color 就弄脏样式树，紧接着的属性读取又触发整棵子树同步重算；
        读写分离后不再交错。

    效果：
        effBg             3275 → 1739 ms   -46.9%
        getComputedStyle   516 →  288 ms   -44.2%
        自愈簇合计         7800 → 6611 ms   -15.2%
        脚本执行时间 scriptMs 9894 → 9596 ms  -3.0%（n=6，两组不重叠）

    等价性验证：29 个视图逐元素比对 inline 样式指纹，全站唯一差异是
    5 个元素多写了一条内联 color，且值与它们原本继承到的颜色完全相同
    → 计算色逐值相同，渲染无差别。58 条交互路径 0 差异，JS 错误 0。

六、edgeone.json 说明
────────────────────────────────────────
  该文件用于设置缓存策略与安全响应头，共 8 条规则：
    /*                → HSTS、X-Content-Type-Options、X-Frame-Options、
                        Referrer-Policy、Permissions-Policy、Content-Security-Policy
    / 和 /index.html  → HTML 短缓存 5 分钟 + 后台静默刷新（stale-while-revalidate）
    /sports-*.js      → 一年强缓存 immutable（含按需加载的 CNKI 数据）
    /portal.*.css     → 一年强缓存 immutable
    /portal.*.js      → 一年强缓存 immutable
    /mountains.*      → 一年强缓存 immutable
    /og-image.png     → 一周缓存
  · 若你的 EdgeOne Pages 项目通过 Git 构建部署 → 会自动读取本文件。
  · 若是控制台直传且不识别本文件 → 请在控制台「规则引擎 / 响应头配置」
    中按 edgeone.json 内的同样内容手工添加（每条规则都有中文注释）。
  · CSP 里保留了 'unsafe-inline' 与 'unsafe-eval'：页面有大量内联样式/脚本，
    且检索逻辑用到了 eval()。若去掉会导致页面功能异常，请勿删减。
  · 第四至六轮改动后 edgeone.json 均无需修改：/sports-*.js 这条规则已经
    覆盖了按需加载的 CNKI 数据文件，用户首次进入论文页拉取后即被强缓存一年；
    defer 只是改变了脚本的执行时机，不影响其 URL 与缓存规则。
